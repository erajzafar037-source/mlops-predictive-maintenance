# Production MLOps: Predictive Maintenance Platform

A reproducible machine-learning engineering project that predicts machine-failure risk from industrial process measurements. It demonstrates the model lifecycle from dataset provenance and leakage-safe preparation through candidate comparison, threshold selection, held-out evaluation, artifact packaging, API inference, containerization and CI.

> **Honest scope:** this is a research/portfolio reference implementation using a synthetic public benchmark. It is not validated for real factory deployment, safety-critical control or maintenance decisions. No live production deployment or measured operational SLO is claimed.

## What this project demonstrates
- Data ingestion from the official UCI repository with source attribution.
- Explicit exclusion of identifiers and failure-mode labels to prevent target leakage.
- Stratified train/validation/test split.
- Comparison of logistic regression, random forest and histogram gradient boosting.
- Candidate selection by validation average precision (PR-AUC), appropriate for an imbalanced failure target.
- Decision-threshold selection on validation data using F2; final metrics are measured on an untouched test set.
- Model pipeline and model card saved as versioned artifacts.
- FastAPI prediction service with input validation, liveness/readiness and model metadata endpoints.
- Docker/Compose workflow, automated tests, Ruff linting and GitHub Actions CI.
- Optional MLflow experiment tracking.

## Dataset and attribution
This project uses the **AI4I 2020 Predictive Maintenance Dataset** from the UCI Machine Learning Repository. It contains 10,000 synthetic observations intended to reflect industrial predictive-maintenance data. The dataset is licensed under **CC BY 4.0**.

- Dataset: https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset
- DOI: https://doi.org/10.24432/C5HS5C
- Suggested citation: AI4I 2020 Predictive Maintenance Dataset [Dataset]. (2020). UCI Machine Learning Repository. https://doi.org/10.24432/C5HS5C.

The data is synthetic. Model quality on this benchmark does not establish performance on real production assets.

## Quick start (Python 3.11+)
```bash
python -m venv .venv
python -m pip install -r requirements-dev.txt
python -m pip install -e .
python scripts/download_data.py
python -m pdm.train --data data/ai4i2020.csv --output artifacts
uvicorn pdm.api:app --reload
```
On Windows PowerShell, activate the venv with `.venv\\Scripts\\Activate.ps1`; on Linux/macOS use `source .venv/bin/activate`. Open http://127.0.0.1:8000/docs for interactive API documentation.

## API
```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"product_type":"M","air_temperature_k":300.2,"process_temperature_k":310.1,"rotational_speed_rpm":1500,"torque_nm":42.0,"tool_wear_min":120}'
```
| Method | Path | Purpose |
|---|---|---|
| GET | `/health/live` | Process liveness |
| GET | `/health/ready` | Model artifact readiness |
| GET | `/model` | Selected model and project version |
| POST | `/predict` | Failure probability and thresholded prediction |

## Evaluation policy
Accuracy alone is not used to select the model because failure events are relatively rare. The validation set selects the candidate using average precision. F2 selects an operating threshold to emphasize recall. The held-out test set is used only for final reporting. Always report the confusion matrix and discuss the cost of false negatives versus false positives before choosing a real-world operating threshold.

Training writes `artifacts/model.joblib`, `artifacts/metrics.json` and `artifacts/model_card.md`. Artifacts and raw data are excluded from Git by default. Commit metrics only when generated by an actual run; do not fabricate performance figures.
